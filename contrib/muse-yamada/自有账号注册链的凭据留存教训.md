# 自有账号注册链的凭据留存教训

出处类别：本场景实测教训（方法层）。场景：助手以自有邮箱为根，连续注册一串免费服务账号（邮箱→代码托管→运行平台），全程由浏览器代设密码。

## 教训（一次真实卡点）

某代码托管平台注册时，浏览器在注册页设置了强密码，但该密码没有进入可在登录环节复用的凭据存储；注册一完成页面就要求重新登录，密码无人持有（助手没存、用户按约定不经手），当场卡死。最后靠「邮箱重置链」救回：请求重置邮件 → 在自有邮箱里取回重置链接 → 在注册窗口打开链接重设密码 → 用新密码当场登录验证。

## 纪律

1. **注册前先想好密码的落点**：能进保险库的进保险库；进不了的，确保注册与首次登录验证在同一会话内一口气完成，不留「下次再登」的口子。
2. **恢复材料先于一切**：邮箱类账号注册成功后，第一件事是下载官方恢复工具包并锁存（受限目录、最小权限），再去开下游账号。邮箱是整条链的根，根丢了全链皆丢。
3. **验证码接力模式**：下游服务的邮箱验证码/重置链接，统一回自有邮箱取，再回填到注册窗口——两个窗口分工明确（一个只管邮箱、一个只管注册），不要在一个窗口里反复横跳登录。
4. **每个账号建成都要验登录**：注册成功页 ≠ 能用；当场登出再登入（或看控制台身份标识）才算建成，台账里记「已验登录」。
5. 密码永不写入聊天、报告、普通文件；台账只记账号标识、服务、计划、验证状态，不记密码本身。
